# 测评指标与边界

## 测试方向

### 服务器到 B站投稿入口

脚本向各 UPOS 主机发送重复的 HTTPS `GET /OK` 小请求，记录：

- `成功率`：curl 成功且 HTTP 状态为 2xx/3xx 的样本比例；
- `DNS`：域名解析耗时；
- `TCP`：解析完成到 TCP 建连完成的耗时；
- `TLS`：TCP 建连后完成 TLS 握手的耗时；
- `TTFB`：从请求开始到收到首字节的累计耗时；
- `总耗时`：整个小请求耗时；
- `P95`：95% 样本不超过的总耗时；
- `抖动`：总耗时样本的总体标准差。

排序首先比较成功率，然后比较 P95 和抖动。高延迟但稳定的线路，通常比偶尔极快、偶尔超时的线路更适合长视频投稿。

### B站到服务器

基础模式只检查 B站静态 CDN 的可达性。传入 `--bvid` 后，脚本通过公共播放接口获取一个公开视频的 CDN 地址，并使用 HTTP Range 下载不超过 `--download-mb` 的数据到 `/dev/null`，统计吞吐和耗时。

公开视频可能因地区、版权、登录要求或风控无法返回播放地址。这种失败不等同于投稿线路失败。

## 动态线路与固定线路

`https://member.bilibili.com/preupload?r=probe` 返回的候选及顺序可能变化。biliLive-tools 的 `auto` 会使用接口提供的候选，因此不同时段可能命中不同 UPOS 主机。

脚本同时维护一份 biliLive-tools 当前线路选择器的已知主机映射作为兜底。同一个实际主机会被去重测试，并在结果中合并显示多个选择器名称。B站调整内部映射后，应以动态探测和实际程序日志为准。

## 评级

- `A`：全部样本成功，P95 与抖动较低；
- `B`：全部样本成功，时延或抖动可以接受；
- `C`：存在失败或明显尾延迟；
- `D`：成功率低，不建议用于生产投稿。

评级阈值是经验值，不代表 B站官方服务等级。正式决策建议使用 10–20 个样本，并在高峰、低峰各测试一次。

## 无法覆盖的部分

安全的小请求无法完全模拟真实视频的分片 PUT、分片重试、合并、投稿提交和稿件审核流程。真实上传还会受到文件大小、分片并发、账号状态、UPOS 服务端负载和 biliLive-tools 删除策略影响。
